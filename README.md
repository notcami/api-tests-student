# API-тесты TestBoard

Тесты для [TestBoard](https://testboard.avito.com/) на Go с использованием `apitest` и `testify/require`.

Документация API: [Swagger UI](https://testboard.avito.com/swagger/index.html), [JSON-спецификация](https://testboard.avito.com/swagger/doc.json).

## Подготовка

Потребуются Git, Go **1.25.1 или выше**, доступ к TestBoard и `golangci-lint` версии 2.

```bash
git clone https://github.com/notcami/api-tests-student.git
cd api-tests-student
git switch main
go mod download
cp .env.example .env.override
```

Зарегистрируйте два разных аккаунта на [странице регистрации TestBoard](https://testboard.avito.com/auth/register). Если аккаунты уже есть, используйте их. Укажите данные в `.env.override`:

```dotenv
TEST_LOGIN=owner@example.com
TEST_PASSWORD=owner_password
TEST_SECOND_LOGIN=reader@example.com
TEST_SECOND_PASSWORD=reader_password
DEBUG=false
```

Первый пользователь создаёт объявления. Второй добавляет их в избранное: своё объявление добавить нельзя. Желательно выделить второй аккаунт для этих тестов. При достижении лимита в его избранном обычное положительное добавление невозможно.

Адрес API уже задан в `.env`:

```dotenv
API_URL=https://testboard.avito.com/api/v1
```

Если нужно сменить стенд, переопределите `API_URL` в `.env.override`. Настройки читаются сначала из `.env`, затем из `.env.override`; локальный файл имеет приоритет. Оба файла находятся относительно корня модуля, поэтому запуск отдельного пакета из IDE также поддерживается. `.env.override` исключён из Git. Пароли и токены в репозиторий добавлять не нужно.

## Запуск

Все тесты с реальными HTTP-запросами к стенду:

```bash
go test -v -count=1 ./...
```

Три последовательных выполнения каждого пакета без кеширования результатов:

```bash
go test -v -count=3 -timeout=20m ./...
```

Отдельные наборы:

```bash
go test -v -count=1 ./tests/scenarios/advertisementCreate/
go test -v -count=1 ./tests/scenarios/favorites/
go test -v -count=1 ./tests/scenarios/advertisementSearch/
go test -v -count=1 ./tests/scenarios/myAdvertisement/
```

Один сценарий:

```bash
go test -v -count=1 -run '^TestCreateAdvertisementWithAllParameters$' ./tests/scenarios/advertisementCreate/
go test -v -count=1 -run '^TestFavoritesLimit$' ./tests/scenarios/favorites/
```

Тест лимита создаёт до 51 объявления, заполняет избранное до 50 записей и затем очищает свои данные. Он выполняется дольше остальных. Для одних и тех же аккаунтов запускайте один процесс тестирования: одновременные независимые прогоны могут менять общий лимит избранного.

Отсутствие настроек авторизации приводит к явной ошибке подготовки, а не к пропуску тестов.

## Проверка оформления и линтер

Установка описана в [официальной инструкции golangci-lint](https://golangci-lint.run/docs/welcome/install/local/). Например, установка проверенной версии в каталог Go:

```bash
curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b "$(go env GOPATH)/bin" v2.15.0
export PATH="$(go env GOPATH)/bin:$PATH"
golangci-lint --version
```

Проверки выполняются из корня проекта:

```bash
golangci-lint fmt --diff
golangci-lint run
go test -v -count=3 -timeout=20m ./...
```

Конфигурация `.golangci.yml` включает проверки ошибок, безопасности, неиспользуемого кода, `govet`, `revive` и `staticcheck`.

## Покрытие

| Набор | Сценарий | Проверки |
| --- | --- | --- |
| Создание | Все параметры и три разных PNG | 201; поля ответа и GET совпадают с формой; поиск по полному названию возвращает созданный id; список фотографий совпадает; файлы скачиваются и побайтово совпадают с исходными |
| Создание | Допустимые границы | Название из 50 символов, описание из 500 символов, количество 100, цена 0 и 1 000 000 сохраняются |
| Создание | Некорректные поля | Нет или пустые title/description; превышение длины; отрицательная, превышающая максимум или нечисловая цена; нулевое, отрицательное, превышающее максимум или нечисловое количество — 400 и точные error/message |
| Создание | Неверное число фотографий | Нет фотографий или передано четыре — 400 и точная ошибка |
| Создание | Неподдерживаемый формат фотографии | BMP — 400, `invalid_request` и сообщение о недопустимом расширении |
| Создание | Нет или неверный токен | 401 и соответствующее сообщение |
| Избранное | Добавление, удаление, повторное добавление | 201/204; созданный id появляется и исчезает в GET /favorites; total меняется на один |
| Избранное | Владелец удаляет объявление | DELETE объявления — 204, GET объявления — 404; запись исчезает из избранного и из total |
| Избранное | Несуществующее объявление | Добавление и удаление — 404 с разными сообщениями; id заранее получен от созданного и удалённого объявления |
| Избранное | Свой товар | 403; список и total не меняются |
| Избранное | Повторное добавление | 409; в списке остаётся ровно одна запись, total не меняется |
| Избранное | Превышение 50 записей | 400; дополнительное объявление отсутствует в списке, total остаётся 50 |
| Избранное | Нет или неверный токен | GET, POST и DELETE — 401; исходное избранное пользователя сохраняется |
| Избранное | Некорректный id | Нет поля, пустой id и неверный UUID при добавлении; неверный UUID при удалении — 400 и точные сообщения |
| Поиск | Части названия и регистр | Поиск по началу, середине и концу; нижний, верхний и смешанный регистр |
| Свои объявления | Созданное объявление в профиле | Совпадение id, владельца, полей и количества фотографий; запрос без/с неверным токеном — 401 |

Для `POST /favorites` покрыты все воспроизводимые прикладные ошибки из Swagger: 400, 401, 403, 404 и 409. Ответ 500 связан с внутренним сбоем сервера; воспроизводить его через исправный публичный API отдельным стабильным сценарием нельзя.

В текущем API получение и удаление одного объявления выполняются через **`/advertisement?id={id}`**, а не через `/advertisement/{id}`. Фотографии доступны по `/advertisements/{id}/photos`.

Ограничения создания проверены на стенде: title — до 50 символов, description — до 500, price — от 0 до 1 000 000, quantity — от 1 до 100, photos — от 1 до 3. У модели редактирования в Swagger указаны другие ограничения длины; для POST используются фактические ограничения создания.

## Организация кода

```text
internal/client/http/           HTTP-запросы, заголовки, multipart-форма
internal/managers/              Проверка статусов, разбор моделей, очистка созданных данных
internal/managers/*/models/     Модели запросов и ответов
internal/helpers/response/      Чтение/закрытие ответа и разбор JSON
internal/assertions/            Общие проверки содержимого ответа
internal/constants/             Пути, лимиты, общие ошибки
internal/utils/                 Настройки и генерация случайных значений
tests/support/                  Авторизация, формы объявлений, PNG-фотографии
tests/scenarios/                Сценарии и проверки поведения
```

Сценарии обращаются к менеджерам; менеджеры используют HTTP-клиентов. Каждый сценарий готовит собственные данные, не требует заранее размещённых объявлений и не использует результат другого теста. Токен каждого пользователя переиспользуется в рамках одного пакета, чтобы повторные прогоны не перегружали ручку входа; объявления и записи избранного между сценариями не переиспользуются. Уникальные названия исключают совпадение с чужими объявлениями. Для отсутствующего id используется удалённое тестовое объявление, а не случайно выбранный идентификатор.

Каждое успешное создание объявления и добавление в избранное регистрирует `t.Cleanup`. Очистка работает и после неудачной проверки. При повторной очистке уже удалённого ресурса допустим 404. Если повторный DELETE объявления вернул 403, очистка отдельно подтверждает его отсутствие через GET с ответом 404. Чужие объявления и существовавшие до теста записи избранного не удаляются. Получение избранного учитывает все страницы.

При `go test -v` выводятся подготовка `[Precondition]`, шаги `[Step]`, статусы `[Result]`, проверки `[Check]` и очистка `[Cleanup]`. В сообщении о неожиданном статусе есть тело ответа. Для полного HTTP-лога можно включить `DEBUG=true`; такой вывод содержит данные запросов, в том числе авторизации.
